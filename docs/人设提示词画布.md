# 人设提示词画布（契约 v1）

把「人设与预设」从一堆散落字段改成**左侧分段编辑 + 右侧最终提示词预览**的工作台。用户只编辑有意义的段落，看到的右侧就是模型实际收到的系统提示词。

## 1. 段落

固定顺序，`id` 稳定，UI 按此渲染；`custom-*` 追加在 `custom` 之后。

| id | 标题 | 类型 | 映射 |
| --- | --- | --- | --- |
| `identity` | 身份 | form | `persona.name` / `age` / `job` / `appearance` / `ownerName` |
| `personality` | 性格 | text | `persona.personality` |
| `background` | 经历与背景 | text | `persona.background` |
| `speech` | 说话方式 | chips | `chat.privateMaxChars` / `groupMaxChars` / `maxBubbles` / `emojiChance` |
| `behavior` | 回复行为 | toggle | `persona.masterRoast` / `proactive` / `opinions` / `newBehavior` |
| `custom` | 补充要求 | text | `persona.customPrompt` |
| `custom-<id>` | 自定义段落 | text | `persona.customBlocks[]` |
| `memory` | 身份关系与记忆 | link | 沿用现有记忆编辑，不进提示词预览 |

规则：

- 空段落不进入最终提示词；`customBlocks` 只允许 10 段、每段 ≤ 2000 字。
- `text` 类型才可自由编辑；`form` / `chips` / `toggle` 在左侧是控件，不做自由文本。
- 学习方式（`styleMode` / `styleScope`）归到 `behavior` 内可折叠小节，不单列卡片。

## 2. 接口

`GET /api/persona/prompt?chatType=private|group&isMaster=1|0`

```json
{
  "ok": true,
  "chatType": "private",
  "isMaster": true,
  "blocks": [
    { "id": "identity", "label": "身份", "kind": "form", "fields": ["name","age","job","appearance","ownerName"], "value": { "name": "助手", "age": 22 } },
    { "id": "personality", "label": "性格", "kind": "text", "editable": true, "text": "…", "defaultText": "…", "maxLength": 500 },
    { "id": "speech", "label": "说话方式", "kind": "chips", "fields": ["privateMaxChars","groupMaxChars","maxBubbles","emojiChance"], "value": {}, "derived": "私聊最多 100 字，最多 2 条，颜文字 0%" },
    { "id": "custom-1", "label": "关于我的工作", "kind": "text", "editable": true, "custom": true, "text": "…" }
  ],
  "system": "……模型实际收到的 system 全文……",
  "tail": "……本轮状态段……",
  "tokens": 3829,
  "warnings": []
}
```

- `system` / `tail` 必须由现有 `buildPromptParts` 用合成消息（私聊、主要联系人、无表情包/无联网）生成，不允许前端自己拼。
- `blocks` 只用于编辑区与定位，不参与最终文本拼装。

`POST /api/persona/block` `{ "id": "personality", "text": "…" }`

- 只接受 `personality` / `background` / `custom` / `custom-*`。
- 校验长度与敏感词；返回 `{ ok, blocks, system, tokens, warnings }`（保存后直接回新预览，UI 不用再请求一次）。

`POST /api/persona/blocks` `{ "title": "…", "text": "…" }` → 新增自定义段落，返回 `{ ok, id, blocks, system }`。
`DELETE /api/persona/blocks/:id` → 删除，返回同上。

`POST /api/persona` 继续承担 `form` / `chips` / `toggle` 的保存；保存后 UI 重新拉 `GET /api/persona/prompt`。

## 3. 提示词接入

`src/persona/prompt.js` 在静态段里按顺序追加 `customBlocks`（标题 + 正文，各占一段），位置在 `custom` 之后、表达偏好之前；空段跳过。旧配置没有该字段时行为逐字节不变。

## 4. 启动器

- 顶部：预设条（应用 / 创建 / 预设管理 / 从文件导入）压缩成一行；右侧显示「已保存」。
- 左侧 55%：段落卡片列表（可滚动），每张卡片标题 + 内容 + 字数；文本段失焦或停止输入 600ms 自动保存。
- 右侧 45%：粘性预览面板，标题「模型收到的提示词」+ 私聊/群聊切换 + token 数 + 复制；正文只读、可滚动，保留换行。
- 底部：「身份关系与记忆」折叠卡，内容沿用现有记忆编辑。
- 不允许再出现：名字/年龄/职业/性格/外观/背景/补充提示词/字数/颜文字/分条/主动行为 各自独立的散块。

## 5. 验收

- 后端：段落映射、自定义段落增删、预览与 `buildPromptParts` 一致（对比 system 全文）、旧配置不变、敏感词拒绝、10 段上限。
- 启动器：`launcher-ui` 覆盖双栏结构、段落卡、预览区、私聊/群聊切换、自动保存、无旧字段散块；深/浅截图。
- 保存后右侧 token 与正文必须变化，不能只在下次打开才更新。
