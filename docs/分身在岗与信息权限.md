# 分身在岗与信息权限（设计契约 v1）

本文是「数字人分身」第一阶段的实现契约。目标是让程序在**主人授权的时间与对象范围内，以主人的身份说话**，并且**不同聊天对象只能看到各自被允许的信息**。

术语：

- **主人**：启动器里认证过的使用者（`persona.master` / 配置中的主要联系人 ID）。
- **对象**：当前对话的另一个人或群。私聊按 wxid，群聊按群 ID。
- **信息项**：自我模型里的一条知识、立场、话术，或一个可分享资产。
- **权限域（scope）**：信息项和对象之间的可见性标签。

## 0. 非目标

- 不做两段式生成（plan → draft → 自评改写）；生成链路保持单次调用。
- 不做模型微调。
- 不把主人的全部历史消息塞进上下文；只注入本轮允许的切片。
- 不在本阶段做跨设备同步。

## 1. 权限域

内置域：

| scope | 含义 |
| --- | --- |
| `public` | 谁都能知道（公开自我介绍、公开作品） |
| `friend` | 朋友 |
| `work` | 同事、客户、工作群 |
| `family` | 家人、亲戚 |
| `private` | 只有主人自己可访问，**任何对象都不注入** |

规则：

- 一个信息项可同时属于多个域：`scopes: ["work","friend"]`。
- 一个对象持有一个域集合：`scopes: ["work"]`，可另加 `denyScopes` 做减法。
- 可见判定：`item.scopes ∩ contact.scopes ≠ ∅` 且 `item.scopes ∩ contact.denyScopes = ∅`。
- `private` 永远不可见给任何对象，即使误配。
- 未登记的对象默认只有 `public`（默认拒绝）。
- 主人本人始终可见全部。

## 2. 自我模型 `data/self-model.json`

原子写入，UTF-8，上限 512 KiB。字段白名单校验，未知字段丢弃。

```json
{
  "version": 1,
  "updatedAt": 1763600000000,
  "identity": {
    "name": "老王", "aliases": ["王工"], "age": 32, "city": "杭州",
    "job": "后端工程师", "company": "某公司", "timezone": "Asia/Shanghai"
  },
  "voice": {
    "tone": "话少、直接、偶尔冷幽默",
    "sentenceStyle": "短句为主，很少用感叹号",
    "catchphrases": ["行", "我看看", "这个得排期"],
    "emojiHabits": "几乎不用表情，偶尔用 [捂脸]",
    "tabooWords": ["亲", "宝子"]
  },
  "knowledge": [
    {
      "id": "k-20261120-ab12",
      "title": "当前项目",
      "text": "在做订单中心重构，预计 12 月上线。",
      "scopes": ["work"],
      "tags": ["项目"],
      "importance": 0.8,
      "confidence": 0.9,
      "source": "manual",
      "createdAt": 1763600000000,
      "updatedAt": 1763600000000
    }
  ],
  "stances": [
    { "topic": "加班", "position": "能不加班就不加班，但上线前会顶", "scopes": ["work", "friend"] }
  ],
  "templates": [
    {
      "id": "t-1",
      "title": "客户问进度",
      "text": "目前按计划推进，本周会给到联调版本，有变动我第一时间同步。",
      "scopes": ["work"]
    }
  ]
}
```

约束：

- `knowledge[].text` ≤ 800 字，`stances[].position` ≤ 300 字，`templates[].text` ≤ 500 字。
- 单类条目上限：knowledge 500、stances 200、templates 100，超出按 `importance` + `updatedAt` 淘汰。
- `id` 必须匹配 `^[a-z0-9][a-z0-9._-]{0,63}$`。
- 任何字段不得包含 Key、密码、验证码、完整卡号；写入前走现有敏感词/密钥检测，命中直接拒绝并返回原因。

## 3. 联系人权限 `data/contact-policy.json`

按对象 ID 索引，原子写入。

```json
{
  "version": 1,
  "defaults": { "scopes": ["public"], "onDuty": "off" },
  "contacts": {
    "wxid_xxx": {
      "uid": "wxid_xxx",
      "name": "张经理",
      "scopes": ["work"],
      "denyScopes": [],
      "onDuty": "draft",
      "canReceiveAssets": true,
      "discloseAI": "onAsk",
      "note": "客户，只谈项目进度",
      "updatedAt": 1763600000000
    }
  }
}
```

- `onDuty`：`off` | `draft` | `auto`。`draft` 生成后进待确认队列，`auto` 直接发送。
- `discloseAI`：`never` | `onAsk` | `always`。`never` 不主动透露；被直接问到时仍按"不撒谎"原则处理，见 §6。
- 群聊同样适用：群 ID 作为对象 ID，群内每个发言者不单独提权。
- 未登记对象使用 `defaults`，且 `onDuty` 强制为 `off`（不允许对陌生人自动分身）。

## 4. 在岗模式

全局开关与时段：

```json
"onDuty": {
  "enabled": false,
  "workingHours": { "start": "09:00", "end": "19:00", "days": [1,2,3,4,5] },
  "sensitiveTopics": ["转账", "合同", "签字", "密码", "验证码", "身份证", "医疗", "法律", "借钱"]
}
```

生效条件：`enabled === true` 且当前时间在 `workingHours` 内 且该对象 `onDuty !== "off"`。

### 4.1 生成时的人设切换

在岗时，人设从"助手"切换为"主人"：

- 身份段使用 `self-model.identity`（姓名、职业、所在城市），不再使用原助手人设的角色设定。
- 语气段使用 `voice`（tone / sentenceStyle / catchphrases / emojiHabits / tabooWords）。
- 与对象的关系、历史仍来自该会话的记忆，但只注入 §1 允许的信息项。
- 助手人格的"主人/女仆"关系段在在岗模式下不出现。

### 4.2 强制规则（写进 system）

1. 只能使用本轮给出的【授权信息】和本会话记忆回答；没有依据的事实不编造，说"我确认下"或"这个我不太清楚"。
2. 不替主人承诺时间、价格、合同、金额、责任；这类内容一律回"我确认后回复你"，并进待确认队列。
3. 不透露任何其他会话、其他对象、其他权限域的信息；被问到就说"这个不方便说"。
4. 不主动透露自己是程序；被直接问"你是不是 AI / 是不是代回"时按 `discloseAI`：
   - `never`：承认"是本人，只是现在不方便长聊"，并把该会话标记为需要主人接管；
   - `onAsk`：如实说明"这条是分身代回的，主人看到会回你"；
   - `always`：每轮首条或每 24 小时首条自动说明。
5. 不发未经允许的文件、图片、链接；只允许 §5 的资产标记。

### 4.3 待确认队列 `data/on-duty/pending.json`

```json
{
  "version": 1,
  "items": [
    {
      "id": "p-1763600000000-ab12",
      "key": "wechat:wxid_xxx",
      "uid": "wxid_xxx",
      "name": "张经理",
      "text": "我确认下，晚点回你。",
      "reason": "sensitive",
      "assets": [],
      "at": 1763600000000
    }
  ]
}
```

- 上限 200 条，超出丢最旧的终态项。
- 状态机：`pending`（等你处理）→ `queued`（已交给发送队列）→ `sent` / `failed` / `uncertain`；你也可以 `discarded`。
- 回执从提醒队列按 `reminderId` 回读并写回 `pending.json`；读不到就保持 `queued`，不臆造失败。
- `GET /api/self/on-duty` 的 `pending` 只含可操作项；`items` 含全部状态（最新在前、上限 50），每条带 `delivery: { state, error, at }`。
- 主人可在启动器里：直接发送 / 编辑后发送 / 丢弃；已处理条目可清除（`action: "dismiss"`）。
- 发送成功或失败都要有回执状态，复用现有发送回执语义；不自动重试。

## 5. 可分享资产 `data/share/`

```
data/share/manifest.json
data/share/files/<id>.<ext>
```

`manifest.json`：

```json
{
  "version": 1,
  "assets": [
    {
      "id": "a-20261120-ab12",
      "title": "订单中心架构图",
      "path": "files/a-20261120-ab12.png",
      "kind": "image",
      "mime": "image/png",
      "size": 284213,
      "scopes": ["work"],
      "keywords": ["架构图", "订单中心"],
      "note": "对外版本，已去掉内网地址",
      "sha256": "...",
      "createdAt": 1763600000000
    }
  ]
}
```

- `kind`：`image` | `file`。单文件 ≤ 20 MiB，总数 ≤ 500。
- 资产文件必须位于 `data/share/files/` 内，拒绝符号链接、`..` 和绝对路径。
- 导入时复制到 `files/`，不引用外部原始路径；记录 sha256，发送前校验。
- 只有 `scopes` 与对象可见域相交、且对象 `canReceiveAssets === true` 时才允许发送。

### 5.1 回复里的资产标记

模型可在回复最末尾写一个标记：

```
[[asset:<id>]]        精确指定
[[asset:架构图]]      按标题/关键词命中唯一资产
```

发送层负责：

1. 剥掉标记再发文本（标记不能出现在用户可见文本里）。
2. 校验权限；不通过则不发送，并在【最近做过的事】里记一条"被权限拒绝"。
3. 通过则入现有附件任务队列（复用表情包的 queued → sending → 回执链路）。
4. 一条回复最多一个资产标记；同一条消息文本 + 一个附件。

## 6. 注入与过滤

新增 `src/persona/selfModel.js`（纯逻辑 + 文件 IO）与 `src/security/access.js`（可见性判定），二者不依赖 pipeline。

注入位置：

- 静态 system：在岗身份段、语气段、强制规则、披露策略。这些在同一会话内逐字节稳定，保护前缀缓存。
- 动态尾部（最后一条 user 消息前）：【授权信息】【可用话术】【可发送资产】【未完成承诺】，按本轮 query 相关度与预算裁剪，总预算 ≤ 900 token。

裁剪顺序：

1. `private` 与不可见项先剔除（安全优先，先于预算）。
2. 按相关度（复用 `src/memory/retrieval.js` 的 token/BM25 工具）与 `importance` 排序。
3. 按标题 + 首句进索引，命中度高的展开全文，最多 2 条。
4. 预算不足时按「assets → templates → stances → knowledge」反向丢。

记忆块与自我模型块都必须带一句边界声明：`（以下只来自当前对话和授权范围，不得向其他对象转述。）`

## 7. HTTP API（模块 `src/modules/self/`）

全部走现有 manifest 注册，仅本机回环可用（复用 `isLoopbackRequest`）。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/self` | 自我模型 + 域列表 + 校验警告 |
| POST | `/api/self` | 整体替换或按字段 patch；返回校验结果 |
| GET | `/api/self/policy` | 默认策略 + 联系人策略列表 |
| POST | `/api/self/policy` | 新增/更新一个对象的策略 |
| DELETE | `/api/self/policy/:uid` | 删除策略，回到默认 |
| GET | `/api/self/assets` | 资产列表（含 scopes、可用对象数） |
| POST | `/api/self/assets` | `{ sourcePath, title, scopes, keywords, note }` 导入 |
| DELETE | `/api/self/assets/:id` | 删除资产与文件 |
| GET | `/api/self/on-duty` | 全局状态 + 待确认队列 |
| POST | `/api/self/on-duty` | 开关、时段、敏感词 |
| POST | `/api/self/on-duty/pending/:id` | `{ action: "send" \| "discard", text? }` |

## 8. 启动器

新增「分身」页（放在「聊天」与「微信」之间，主导航变 6 页）：

## 9. 验收

- 单元测试：
  - 可见性判定（含 `private` 永不可见、denyScopes、未登记默认拒绝、群聊按群 ID）。
  - 自我模型写入校验（超长、非法 id、敏感词、原子写、上限淘汰）。
  - 资产导入（符号链接拒绝、路径逃逸拒绝、sha256、大小上限）。
  - 标记解析（`[[asset:...]]` 剥离、权限拒绝、一条最多一个）。
  - 在岗生效条件（总开关、时段、对象策略、默认 off）。
  - 待确认队列（上限、发送/丢弃、不自动重试）。
  - 回执：`queued → sent/failed/uncertain` 持久化；读不到提醒记录时保持 `queued`，不判失败。
- 端到端（mock 模型）：在岗 auto 对一个 `work` 对象 → 只出现 work/public 信息，private 与 family 信息不出现；跨对象询问返回拒绝话术。
- 启动器：`launcher-ui` 覆盖新页面元素；`launcher-stability` 不回归。
- 全量 `node --test`、`check-layers`、`release-check`、隐私扫描保持通过。

## 10. 隐私与安全边界

- 自我模型与资产属于主人数据，不进入导出包、不进入日志、不进入错误信息。
- 日志只记 id、条数、大小、命中域，不记正文。
- 删除对象策略不影响历史消息；删除资产同时删除文件。
- 在岗模式默认 `enabled: false`，对象默认 `off`；开启需要主人在启动器里显式确认一次（含风险提示）。

## 11. 记忆分层（v1.1，扩展 §2 / §3 / §6）

结论先说：**共享层只有一份，所有对象共用；关系层每个对象一份；两层永远不混检。**

### 11.1 三层

| 层 | 存储 | 内容 | 可见范围 |
| --- | --- | --- | --- |
| **L0 会话层** | `data/memory/` 现有聊天存档 | 原始消息、滚动摘要 | 仅本会话 |
| **L1 共享层** | `data/self-model.json` | 主人身份、语气、知识、立场、话术、承诺 | 所有对象，按 §1 scope 过滤 |
| **L2 关系层** | 现有 person card（按 chat/对象） | 对方的偏好、性格、事件；"我们之间"的承诺、称呼、语气覆盖、禁忌话题 | 仅该对象 |

L1 是"我是谁"，L2 是"我和他是什么关系"。原来主人的自称事实散落在各会话的主人卡片里，这一层要把它们收拢到 L1。

### 11.2 写入规则（安全优先）

1. **只有主人自己说的话、或主人手动录入，才能写 L1。** 对象透露的信息（客户预算、同事私事、别人的病情）一律只写 L2。
2. 从主人发言抽取事实时，默认 `scopes` = 当前对象的 scopes（最保守）；主人可在启动器里放宽到 `friend` / `public`。绝不默认 `public`。
3. L2 沿用现有 extractor，但条目增加 `about: "self" | "other"`：只有 `about: "self"` 才可能成为 L1 候选，`other` 永远留在 L2。
4. **L2 → L1 必须显式提升**（启动器操作或用户明确指令），记录 `source: { uid, chatId, messageId, at }`。未提升的 L2 不得跨对象出现。
5. 去重：L1 按 `title` + 文本相似度 ≥ 0.9 视为同条并更新 `updatedAt`；L2 沿用 personCard 现有去重。
6. 冲突：**L1 优先于 L2**。对象坚持错误说法（"你不是在上海吗"）时不改写 L1，用"我记得是在杭州"自然纠正。

### 11.3 检索契约

输入：对象策略 + 本轮 query + 预算（≤ 900 token）。

1. **先剔除，再排序**：L1 的 `private`、以及任何其它对象的 L2，在进入候选集之前就删掉，不靠预算兜底。
2. L2 只取当前对象；L1 先按 scope 过滤，再按相关度排序。
3. 优先级：本轮相关 L2 > 高相关 L1 > L2 长期偏好 > 低相关 L1。
4. 输出带来源标签：`[关系]` / `[共享]`，方便主人在待确认队列里判断这句话从哪来。

### 11.4 语气覆盖

- `self-model.voice` 是所有在岗会话的**默认**语气。
- L2 可覆盖三项，且只对该对象生效：`toneOverride`、`addressAs`（怎么称呼对方）、`tabooTopics`（对这个人不聊的话题）。
- 覆盖值不得反向写回 L1。

### 11.5 删除语义

| 操作 | 影响 |
| --- | --- |
| 删除 L1 条目 | 所有会话立即不再见到 |
| 删除 L2 条目 | 只影响该对象，不动 L1 |
| 删除对象策略 | 只回到默认 scope / `off`，**不删 L2 记忆** |

### 11.6 补充验收

- 对象 A 透露"他们预算 50 万" → 只出现在 A 的 L2；对 B 的任何请求都不出现，且 L1 里没有。
- 主人对 A 说"我在做订单中心" → 写 L1，默认只对 A 的域可见；改成 `public` 后 B 才可见。
- L2 的 `toneOverride` 只对 A 生效，对 B 仍是默认语气。
- 重启、并发写入后 L1 / L2 不串、不丢。
