# 启动器测试与提权

## 为什么正式版必须提权

`launcher/app.manifest` 是 `requireAdministrator`：桥接要读被微信占用的 UI 线程、改 UIA gate 字节，必须和以管理员运行的微信同级，否则批量发送、读消息都会失败。

代价是**每次启动都弹一次 UAC**。这条不能为了测试方便改掉——改了之后普通用户拿到的是连不上微信的版本。

## 测试和截图怎么跑

用测试构建，manifest 走 `launcher/app.test.manifest`（`asInvoker`），从根上不弹 UAC：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/build-test-launcher.ps1
# 产物：artifacts/test-launcher/WhaleLauncher.exe
powershell -ExecutionPolicy Bypass -File scripts/build-test-launcher.ps1 -Launch
```

脚本会做三件事，缺一不可：

1. 用 `-p:WhaleTestBuild=true` 发布到 `artifacts/test-launcher/`；
2. 读产物 PE 里嵌入的清单文本，确认是 `asInvoker`、不是 `requireAdministrator`（防止 obj 缓存或参数没生效）；
3. 拒绝把产物指到仓库根目录，避免覆盖正式 `WhaleLauncher.exe`。

## 正式版怎么发

```powershell
powershell -ExecutionPolicy Bypass -File scripts/publish-launcher.ps1
```

为什么不能直接 `dotnet publish`：测试构建和正式构建**共用 `launcher/obj`**。asInvoker 的中间产物会留在里面，增量发布会直接复用它，正式 EXE 就会悄悄变成免提权版——桥接随后读不到管理员运行的微信，而且只有到真机发送失败时才会发现。

所以正式发布脚本先 `dotnet clean`，发布后再读 PE 清单自证 `requireAdministrator`，不是就直接失败。测试脚本跑完也会自动 clean。

## 边界

- 测试构建**连不上以管理员运行的微信**：只适合界面、配置、离线接口、截图、纯协议用例。
- 需要真实微信通道的验证（发送、桥接日志、回执）仍然要用正式提权版本，人工点一次 UAC，或者在一台允许免 UAC 的测试机上跑。
- 不要把 `artifacts/test-launcher/WhaleLauncher.exe` 复制到根目录，也不要提交它。
- `tests/launcher-test-build.test.js` 锁住：正式清单仍是 `requireAdministrator`、测试清单不带提权、只有测试构建脚本会打开 `WhaleTestBuild`。
